# Tool Catalog (CLI subcommands + Web API endpoints)

> This file is the **tool documentation** — SKILL.md only covers workflow (issue #133 Decision 6:
> Tool Usage is delegated to MCP schema auto-discovery; the Skill shrinks to the orchestration protocol).
>
> - **MCP users** (Claude Code plugin / codex mcp): the tools come with auto-discovered schemas,
>   so you usually don't need this file; only consult this table for the long-tail endpoints MCP
>   doesn't cover (trades/config/events/...)
> - **CLI/REST agents** (Gemini / Cursor / scripts): this file is the complete reference

## Subcommand overview

| Command | Path | Use for | Returns |
|------|------|------|------|
| `doctor` (MCP: `doctor` tool) | Universal | Mandatory first step | JSON, `status: "ready"` or `"needs_setup"`. `needs_setup` only when memory isn't initialized (or `portfolio.md` is still v1). A missing LLM key / mail credentials / `.env` never changes it: those `checks` carry `optional_for_coordinator` / `optional_for_email` (Coordinator needs no key; `direct_ready` says whether Direct does). A `warning` check (`gold_booking`: legacy GC=F row not in CNY per gram, which also makes the daily DCA fail) is a data fix, not an onboarding gap — it never changes `status` |
| `init [--from-stdin] [--force]` | Universal | **Not used in this skill** — first-time installation goes through the `invest-setup` skill | — |
| `status` | Universal | View portfolio | cash + holdings + live prices + P&L + `performance` (same block as below); each `all_holdings[]` row carries `alerts` (the user's per-asset alert lines with `distance_pct` / `breached` / a ready-made `text` such as "距 price_below 还有 3.2%"; empty list = none set; a tracked asset with lines but no holding row shows as an `is_tracking_only` row) |
| `performance` | Universal | Real-account performance: "how am I doing / 我的收益率 / 跑赢大盘没" | TWR 30d / YTD / since inception, XIRR (money-weighted, needs ≥30 days), max drawdown with peak→trough dates, annualised volatility, return vs the configured benchmark (`portfolio.benchmark_symbol`, default 510300.SS) and `data_quality` (forward-filled days, cost-fallback symbols, `unreconciled` = opening position inferred from `portfolio.md` − ledger) plus `price_basis` per symbol (`raw` = split-adjusted price without dividend adjustment, used once `close_raw` is backfilled so ledger dividends aren't counted twice; `adjusted` = fallback, also always for gold-per-gram and OTC funds). `{"status": "insufficient_history"}` until the ledger spans 2 trading days. Base currency, zero LLM |
| `strategy` | Universal | View strategy | target_assets + Dreaming insights |
| `history [-n N]` | Universal | View the transaction log | last N trades + committee verdicts |
| `live_prices` | Universal | Background market data | VIX / TNX / USDCNY / AUDCNY / NDQ / GC=F |
| `discipline` | Universal | "what did the committee block / how is my discipline" (委员会拦了什么/纪律如何) | inaction rate (HOLD share of **live** verdicts) + count of blocked impulsive actions + counterfactual money saved/lost (read-only, zero LLM, aligned with ADR-023). Equivalent to `GET /api/discipline` |
| `decisions [--days N] [--symbol S] [--verdict V] [--limit N]` | Universal | "how many recommendations did I follow / which ones weren't executed" (我听了几次建议/哪些没执行) | verdict↔intervention↔execution↔outcome join + adoption rate (read-only, zero LLM). Lists the newest 20 by default (`--limit 0` = all); `count` / `summary` cover every match. Same data as `GET /api/decisions` (issue #133 Decision 9) |
| `explain_decision DECISION_ID` | Universal | "why was today's verdict HOLD / why did it tell me to sell" (为什么今天是 HOLD/为什么让我卖) — replay one past verdict. `DECISION_ID` is `<date>/<symbol>` exactly as `decisions` prints it, e.g. `2026-07-03/GC=F` | verdict / confidence / alloc_cny + `confidence_lookup` (quote this next to the verdict, not the self-reported confidence) + the full 4-role debate `transcript_markdown` with the CIO memo (render it) + `path_snapshot` (may be null; always null in REST remote mode, whose hub endpoint doesn't serve it). Read-only, zero LLM. Same output as MCP `explain_decision` |
| `ingest_event` | Write | agent feeds news into the event ledger (severity grading, idempotent). Pass your own `--claim --stance --severity [--symbols --entities --event-type]` and no backend model is needed; without them the backend LLM normalizes it (fails in keyless agent mode). Holding-relevant severity ≥ mid non-neutral items auto-trigger a rate-limited committee re-run (`committee_task_id` in the result; `queued:<id>` in agent mode); disabled in advisory mode | `--title --url [--snippet --source --ts --claim --stance --severity --symbols --entities --event-type]` |
| `pending_news` | Read/write | Agent mode (keyless backend): news the backend fetched but did not normalize. `ingest_event` the relevant ones with your own claim/stance/severity; pass the rest to `--dismiss`. Items expire after 48h | `[--limit N] [--dismiss URL ...]` |
| `pending_committees` | Read | Agent mode: committee re-runs that events / price moves requested. For each: `prepare_committee` → roles → `save_committee`; done once a newer verdict is saved. Expire after 24h | — |
| `record_execution DECISION_ID [--rejected] [--reason "..."]` | Universal, write | Write back when the user says "I didn't buy / I bought it" (我没买/我买了) | Idempotent append to executions.jsonl. **When the user rejects a recommendation, proactively ask why before recording** (you are the collection end of the Reason Loop). Equivalent to `POST /api/decisions/execution` |
| `what_if [--symbol X --pct N \| --gold-pct N \| --ndq-pct N]` | Universal | "how much do I lose if X drops Y%" (X 跌 Y% 我亏多少) | Arithmetic scenario, no LLM |
| `rebalance_plan [--mode hybrid\|cash_only\|sell_to_rebalance] [--band-pct N]` | Universal | "do I need to rebalance / what should I buy or sell to get back to target" (要不要再平衡/该买卖多少) — compares holdings with `strategy.md` targets (`target_assets[].target_pct`; assets without one split `target_allocation_stock` equally, marked `target_source: equal_split`). Equivalent to MCP `rebalance_plan` | List only, places no order: `rows` (per asset: current/target/drift pct, `action` BUY/SELL/NONE, `amount` in base currency, `units` rounded down to whole lots — A-share 100, convertible bond 10, off-exchange fund by amount, HK/others 1 with `lot_note`, `reason`), `totals` (cash_after / turnover / n_trades), `unmanaged`, `warnings`. Within ±band (default 5pp) → NONE. Modes: `cash_only` spends only cash above the target cash ratio and never sells; `hybrid` (default) uses that cash first and sells overweights only to cover the gap; `sell_to_rebalance` sells every overweight back to target. Read-only, zero LLM |
| `correlate --symbols A,B[,C...] [--period 6mo] [--with-llm]` | "btw" side-query | The user **asks in passing** "do A and B move alike?" (A 跟 B 像不像) (no writes to memory/.committee; pure query, returns results) | pairwise correlation matrix + sector + macro linkage |
| `prepare_committee SYM` | Coordinator | Get the brief for the 4 subagents | brief JSON + 6 prompt sections |
| `save_committee SYM [--provider P] [--model M]` | Coordinator | Persist the transcript to disk. Pass `--provider` (your brand) and `--model` (the model that plays the 4 roles); the scorecard buckets by `<provider>:<model>`, omitted model = `unknown` | 4-section output via stdin → markdown |
| `run_committee SYM [--force]` | Direct | One-shot full committee | verdict JSON + CIO memo |
| `deposit -c CCY -a N` | Universal, write | Deposit cash (any currency) | JSON new balance |
| `withdraw -c CCY -a N` | Universal, write | Withdraw cash; errors on insufficient balance | JSON new balance |
| `buy --symbol S --units N --price P [-c CCY] [--kind etf/equity/...] [--existing-position]` | Universal, write | Add to / open a position (weighted average cost), paid from ledger cash (refuses if cash is short). `--existing-position` (MCP: separate tool `record_existing_position`; an older MCP server answers `Unknown tool` — don't fall back to `buy`): record a position the user held **before** onboarding that `status` doesn't list yet (re-adding a listed symbol counts it twice) — cash unchanged, history `funding_source: external_funding`, `source: skill_cli:existing_position`; refused in REST remote mode. Does not add the symbol to `target_assets` (that's `track_asset`). **Gold = `GC=F` only in CNY per gram** (`-c CNY --kind metal --unit-label 克`, `--units` = grams, `--price` = CNY/gram); any other currency/unit is rejected with the correct form | JSON action + estimated cost + `funding_source` |
| `sell --symbol S --units N --price P` | Universal, write | Reduce a position (returns cash per the holding's cost_currency) | JSON remaining units |
| `record_dividend --amount N -c CCY [--symbol S] [--kind dividend\|interest] [--tax-withheld T] [--reinvest [--reinvest-price P]] [--trade-date D] [--note T]` | Universal, write | Record a dividend you already received (cash + `N − T`, position unchanged; `--reinvest` = DRIP: a second ledger row buys more of S at `--reinvest-price`, default the stored raw close) or, with `--kind interest`, interest (symbol optional). Internal flow: counts as return, not a deposit. A symbol that is neither held nor in the ledger is rejected. `--trade-date` = the day the cash arrived (YYYY-MM-DD, default today) — pass the real date when back-filling. All write subcommands take `--idempotency-key` | JSON net cash + new balance |
| `record_fee --amount N -c CCY [--kind fee\|tax] [--symbol S] [--trade-date D] [--note T]` | Universal, write | Record a fee (account fee, remittance, standalone commission) or `--kind tax` (e.g. dividend tax settled afterwards): cash − N, an account cost not a withdrawal. Errors if the currency's cash is lower than N. Trade commissions need no entry (buy/sell already book the trade) | JSON new balance |
| `record_split --symbol S --ratio R [--trade-date D] [--ledger-only]` | Universal, write | Record a split / reverse split: units × R, average cost ÷ R, cash unchanged. `R` = new/old (10-for-1 → 10; 1-for-10 → 0.1). `--trade-date` = ex-date: account performance restates earlier trades to post-split units from it. **Refused** when the ledger already has trades/corrections for S on or after `--trade-date` (they were booked in post-split units, so multiplying the whole snapshot would invent shares); if the snapshot units are already post-split, add `--ledger-only` (writes the ledger row only, units/cost untouched). Not idempotent without `--idempotency-key` (a second call multiplies again). Afterwards run `backfill_raw_close --symbols S` if the account is older than 2 years | JSON new units + average cost + `follow_up` |
| `record_return_of_capital --symbol S --amount N -c CCY [--trade-date D]` | Universal, write | Record a return of capital: cash + N, average cost − N/units (a cost reduction, not income), units unchanged; cost floors at 0 (`excess_over_cost` reports the rest). Currency must equal the holding's cost currency | JSON new average cost |
| `place_fund_order --symbol FUND:NNNNNN --amount N [-c CNY] [--order-ts ISO] [--note T]` | Universal, write | Off-exchange fund purchase, step 1: cash − N now, the order is tracked as in transit (`holding.extra.pending_orders`, listed in `status.pending_fund_orders`). Total assets are unchanged (in-transit counts at face value). `--order-ts` = when the order was placed, Beijing time ISO (default now): before 15:00 on a trading day → priced at that day's NAV, otherwise the next trading day's (`nav_date`); expected confirm date = pricing day + lag trading days (QDII / FOF slower, from the fund profile; `fund.confirm_lag_days`), Mon–Fri calendar, no holiday table → an estimate (`calendar`, `lag_source` say so). A `510300.SS`-style exchange code is refused (use `buy`). Takes `--idempotency-key` | JSON `order_id`, `nav_date`, `expected_confirm_date`, new cash balance |
| `confirm_fund_order --order-id ID [--nav N] [--fee F]` | Universal, write | Step 2: turn an in-transit order into shares at the pricing day's NAV (`units = (amount − fee) / nav`, average cost weighted by the order amount). The `fund_confirm` job does this every weekday evening, so run it only to supply a NAV / fee or confirm early. Safe to repeat: already confirmed → `already_confirmed`, cancelled → `cancelled`; NAV not published yet → `pending_nav` (nothing changes); pricing day with no NAV (holiday) → the next published NAV day is used and `nav_date_planned` says so | JSON `units`, `nav`, `nav_date`, new average cost |
| `cancel_fund_order --order-id ID` | Universal, write | Cancel an order still in transit (cash returns). A confirmed order is refused — use `sell` | JSON cash returned |
| `backfill_raw_close [--symbols A,B]` | Operator (run once after upgrading) | Backfill `daily_prices.close_raw` (raw close, split-adjusted but not dividend-adjusted) for existing market-DB rows: networked yfinance `period=max`, UPDATE-only, idempotent. Default = holdings + `target_assets`; OTC funds and the gold-per-gram proxy are skipped (no dividend-free series / no dividends). Without it every symbol stays `price_basis: adjusted` | JSON per-symbol `updated` / `null_rows` |
| `delete_holding --symbol S [--force]` | Universal, write | Delete a holding row (units must be 0, or use --force) | JSON deleted |
| `import [--file F \| --text T] [--commit]` | Universal, read/write | Free-text/CSV holdings description → LLM-parsed structured holdings (broker-position paste, bulk entry). Preview-only by default; `--commit` performs a non-destructive write (only adds new symbols; cash only fills currencies currently at 0; re-importing is idempotent). Equivalent to POST /api/holdings/import. `parsed.warnings` (present only when non-empty) names each off-exchange fund whose amount could not be converted to units (stays 0 units) — tell the user | JSON `{parsed, committed, summary?}` |
| `config [--set KEY VALUE] [--clear KEY]` | Universal, read/write | Read/modify the whitelist of API-configurable parameters (concentration_lens / **cash_opportunity_cost_rule** (opportunity-cost rule, default OFF, ADR-024) / risk_profile / gold_defense_dca / dreaming.llm_verify / **dca.auto_dca_enabled / dca.auto_dca_amount_cny** — auto-DCA switch and amount, ADR-018 / **event.watch_schedule** — event_watch scan-window crontab (interpreted in Asia/Shanghai; default Beijing 8:00 to 2:30 next day; the scheduler picks changes up automatically within ≤10 minutes, no restart needed) / **event.sentinel_enabled / event.sentinel_atr_mult / event.sentinel_cooldown_min / event.sentinel_schedule** — price-anomaly sentinel (vertical-move detection; sends an alert email first, then triggers the committee, ADR-025): master switch / trigger multiple (× daily ATR, default 0.8) / cooldown minutes for the same symbol + same direction (default 120) / scan-window crontab (default every 5 minutes). There are also several event.*/staleness.* keys — see GET /api/config for the full list). No args = read everything. Equivalent to GET/PUT /api/config (ADR-017) | JSON of all effective values |
| `maintenance cleanup [--dry-run\|--apply] [--keep N] [--days D]` | Operator (not for daily agent use) | Prune `memory/*.bak.<timestamp>` backups (keep newest N per family OR younger than D days; defaults 20 / 7) and stale `*.lock` sidecars. **Dry-run by default** (counts only); `--apply` deletes. Local only — works on this machine's data dir even when `INVEST_API_BASE` is set | JSON with per-category counts |
| `track_asset --symbol S [--display-name N] [--channel C] [--max-single-invest-cny N] [--price-offset-pct P] [--sell-fee-pct P] [--target-pct W] [--alert-price-above P] [--alert-price-below P] [--alert-day-drop-pct X] [--alert-day-rise-pct X] [--alert-drawdown-from-cost-pct X]` | Universal, write | Add or update a tracked asset in `target_assets` (committee coverage; places no order, touches no holdings). A new asset without `--max-single-invest-cny` inherits the strategy's single-entry cap; on an update, pass only the fields you change. `--target-pct W` (MCP `target_pct`) = this asset's target weight as a 0–1 share of **total** assets, read by `rebalance_plan`; the weights of all tracked assets must sum to ≤ `target_allocation_stock`, otherwise the write is rejected and the error shows the current sum. `--alert-*` (MCP `alert_price_above` / `alert_price_below` / `alert_day_drop_pct` / `alert_day_rise_pct` / `alert_drawdown_from_cost_pct`) = per-asset alert lines the price sentinel checks every few minutes (price lines re-alert at most once per 24h; `day_*` lines once per market trading day — on a closed market they still describe the last session), stored in `target_assets[].alerts`: `price_*` in `status.current_price`'s unit, `*_pct` in percentage points (3 = 3%), `drawdown_from_cost` only for held assets; each flag overwrites just that line (clear with `set_allocations --alert`). **Delivery needs `INVEST_EVENT_ALERT=1` on the server (default off — otherwise a hit is only logged, nothing is sent); a hit never starts a committee run** | JSON |
| `untrack_asset --symbol S` | Universal, write | Stop tracking an asset (removes it from `target_assets`; holdings are not touched) | JSON |
| `set_allocations [--stock X --cash Y] [--target-pct SYMBOL=W ...] [--alert SYMBOL:RULE=V ...]` | Universal, write | Set the target stock / cash ratios (0–1 each, pass both) and/or per-asset target weights (`--target-pct`, repeatable; MCP `target_pcts` map; `SYMBOL=none` clears one; the symbol must already be tracked) and/or per-asset alert lines (`--alert GC=F:price_below=900`, repeatable; RULE ∈ `price_above` / `price_below` / `day_drop_pct` / `day_rise_pct` / `drawdown_from_cost_pct`; MCP `alerts` map `{symbol: {rule: value}}`; `SYMBOL:RULE=none` clears one line, `SYMBOL=none` clears all of that symbol's; unnamed lines are left alone). Everything in one call is validated and written atomically — lower the stock target and the weights together, or the intermediate sum would exceed it and be rejected | JSON |
| `news_sources [--add NAME URL] [--remove NAME_OR_URL]` | Universal, read/write | No args: list news sources (built-in + your extra RSS feeds). `--add` adds a feed after a live probe; `--remove` deletes one of your extra feeds | JSON source list |
| `event_check [--live] [--recall SYMBOL]` | Universal | Run one news-sentinel scan. Dry-run by default (no email, no committee); `--live` sends alerts and triggers the committee; `--recall SYMBOL` only tests event recall for that symbol | JSON summary |
| `daily_report` | cron | Full daily report over all tracked assets, with email. Burns LLM tokens — **do not run it proactively in conversation** (see SKILL.md constraints) | report |
| `autopilot_daily` | cron (operator, separate `INVEST_HOME` only) | Paper-account daily flow: `daily_report` (no email) → `paper_autopilot` (books today's directional verdicts on the local ledger at the day's close; **no-op unless `autopilot.enabled`**, never places real orders) → `verdict_review`. Burns LLM tokens and writes the ledger — **never run it in conversation or against a real account's `INVEST_HOME`**; see `experiments/paper_autopilot/` | JSON per stage |
| `ibkr_autopilot {pick,decide,submit,reconcile,daily,status} [--force]` | cron (operator, separate IBKR `INVEST_HOME` only) | **Places REAL orders** in the configured Interactive Brokers account when `ibkr.enabled` is on and `ibkr.dry_run` is off (default dry run = `whatIfOrder` only; `ibkr.*` is not settable through `config`). `pick` = LLM picks ≤5 US stocks/ETFs into `target_assets` (Mondays; `--force` now); `decide` = LLM writes today's orders, with the committee's verdicts as reference input only; `submit` = today's orders → capped DAY limit orders (+ sells holdings no longer picked); `reconcile` = books the last 7 days' fills (stocks + in-account FX), halts on position drift; `submit` also converts AUD→USD inside the account when USD runs short; `daily` = pick → `daily_report` (no email) → decide → submit → `verdict_review`; `status` = **read-only** snapshot (broker cash / positions / open orders / today's fills + ledger + list + today's orders + halt flag) — the one phase that is safe to run in conversation. **Never run the other phases in conversation** — they need the local IB Gateway (weekly IB Key approval by the account holder) and move real money; see `docs/wiki/24-ibkr-autopilot.md` | JSON per stage |

**The subcommand names are a closed set — any command not in the table above does not exist.**
When you catch yourself wanting to call `get_committee_context` / `analyze_asset` / `pull_brief`
or names like that, stop and check against the table — you are most likely hallucinating a
nonexistent command name and should pick `prepare_committee` or `run_committee` instead.

All output is JSON. **Always quote numbers from the JSON**, never from the `memory/*.md`
markdown (the markdown body is rendered from the frontmatter and may lag slightly behind).

### Importing holdings from broker-app **screenshots** (you do the OCR; zero backend dependency)

When the user sends a **screenshot** of broker holdings: **read the image yourself** (you have
vision), convert each row into text as `symbol/units/cost/currency/channel`, then run
`import --text "..."` (or POST /api/holdings/import). The backend `import`'s LLM parses **text
only** — do not feed it the image (DeepSeek and most chat models don't accept images and will
error). In short: screenshot → you transcribe to text → import. This is more accurate than
backend OCR and doesn't depend on the backend model. Run `--text` first (without `--commit`)
so the user can verify the preview, then `--commit` for the non-destructive write.

## Web API write endpoints (agents can call these too)

**Product philosophy**: the agent (you) has access to ALL of openInvest's functionality.
**Prefer CLI subcommands / MCP tools**; only curl the endpoints below (default :8765) for
long-tail operations not covered by CLI/MCP. The Web API is marked deprecated (the GUI is
retired; the remaining endpoints serve remote hub mode, and no new endpoints will be added).
For remote scenarios, prefer the hub's remote MCP (`openinvest-mcp --http`, all tools direct);
REST forwarding only backfills the long tail MCP doesn't cover.
If the hub sets `INVEST_API_TOKEN`, every `/api/*` call (except `/api/health`) must carry
`-H "Authorization: Bearer $INVEST_API_TOKEN"` — loopback included; otherwise it returns 401.

Call these when the user says "record a trade" (记一笔交易) / "I plan to buy X" (我打算买 X) /
"mark as executed" (标记成交) / "add a new asset" (加新资产):

| Endpoint | Use for | Example body |
|------|------|-----------|
| `POST /api/trades/record` | **Record an intended trade** (no real payment connection; internal ledger only) | `{symbol, direction: "BUY"\|"SELL", units, price?, intended_date?, note?}` |
| `GET /api/trades?limit=N` | View the last N intended / executed trades | — |
| `PATCH /api/trades/{id}/status` | **Mark as executed** (status: "executed") → auto-syncs portfolio.md (updates holdings + deducts cash) | `{status: "executed"}` |
| `POST /api/holdings` | Add a yfinance-tracked asset (places no order; only records holding data) | `{symbol, kind, units, avg_cost, cost_currency, channel?}` |
| `POST /api/holdings/import` | Free-text/CSV holdings description → LLM parse (broker-position paste, bulk entry). `commit:false` previews only, no write; `commit:true` non-destructive write (only adds new symbols; cash only fills currencies currently at 0). Requires backend LLM key | `{content, commit?}` |
| `PUT /api/holdings/{symbol}` | Modify holding fields | `{units?, avg_cost?, channel?}` |
| `POST /api/skill/deposit` / `/withdraw` | Adjust cash (same implementation as CLI/MCP `deposit`/`withdraw`; optional `idempotency_key` in body or `Idempotency-Key` header) | `{currency: "CNY"\|"AUD"\|..., amount}` |
| `POST /api/skill/buy` / `/sell` | Record a buy/sell of any holding, gold (`GC=F`) included (same implementation as CLI/MCP `buy`/`sell`; optional idempotency key as above) | `{symbol, units, price, currency?}` |
| `POST /api/strategy/asset` | Add a target_assets entry. **Native equivalents already exist**: MCP `track_asset` / CLI `track_asset` (plus `untrack_asset`, `set_allocations`) — prefer the native ones; stop curling this | `{symbol, channel?, max_single_invest_cny}` |
| `GET /api/events/recent?hours=24&min_severity=low&limit=50` | List news perceived by the event layer in the last N hours (ADR-006). For debugging / "what is the system currently aware of" (系统现在感知到什么) | — |
| `GET /api/discipline` | Committee discipline ledger: inaction rate (HOLD share of live verdicts) + count of blocked impulsive actions + counterfactual P&L (aligned with ADR-023; lets the agent show "what it blocked") | — |
| `GET /api/verdict_review/summary` | Verdict hit rates split into `live` / `backtest` / `contaminated` buckets (ADR-022). | `GET /api/decisions?days=90` | Unified decision view: verdict↔intervention↔execution↔outcome join + adoption rate (issue #133 Decision 9) | — |
| `POST /api/decisions/execution` | Write back the user's execution/rejection of a verdict + the reason (idempotent, ADR-016) | `{decision_id: "2026-07-03/GC=F", executed: false, reason?: "..."}` |
| `POST /api/events/check` | Manually run event_watch once (fetch news + normalize + store + trigger the committee on hits). Synchronous, 30-90s | — |
| `GET /api/config` | View the current effective values of the API-configurable whitelist parameters (+ whether overridden + metadata) | — |
| `PUT /api/config` | Set one whitelist override (persisted to disk, shared across processes, takes precedence over env; ADR-017) | `{key, value}`, e.g. `{"key":"verdict.concentration_lens_enabled","value":false}` |
| `DELETE /api/config/{key}` | Delete an override, reverting to the default | — |

**Typical flow**: the user says "I plan to..." (我打算...) / "just bought X" (刚买了 X) / "my
position in Y grew" (我的持仓多了 Y) → use `POST /api/trades/record` (with intended_date to
distinguish planned vs executed) → once actually executed, use `PATCH .../status executed`;
the backend **automatically updates portfolio.md** (weighted average cost + cash deduction) —
you don't need to call anything else.

**Full OpenAPI**: `http://127.0.0.1:8765/openapi.json` lists every endpoint + Pydantic schema.

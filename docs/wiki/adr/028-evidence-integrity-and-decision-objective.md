# ADR-028：决策目标、证据资格和恢复边界

状态：实现须通过隔离测试、独立工程/数据/统计评审后部署。

## 目标

系统提供基于当时可用信息、可复核的投资建议。HOLD 多、交易多、拦截多，都不能单独证明系统有效。HOLD 可以合理，但不能成为默认成功标签。此决定修正 ADR-023 把“不作为”直接视为可证价值的产品解释；保留其不夸大预测能力的要求。

市场方向、用户约束、执行可行性、数据可信度分别记录。资金不足不改变市场方向；crash 标签不自动等于 neutral。缺输入显示 DATA_UNTRUSTED；规则阻止动作显示受约束及具体规则。评分尺子和用户权限不由学习器自行放宽。

## 先取证，再修复

1. 记录运行实例、有效参数、代码/提示词、自动任务状态。
2. 停止污染传播，保存原始数据及代码配置，记录每个库的水位和采集时点。
3. 验证副本可读及哈希；单库一致不能冒充账户、券商、文件系统之间的原子切点。
4. 先验证系统级测试隔离，再运行测试和迁移。隔离必须拒绝直接、临时写后删除、符号链接、子进程越界写；外网和宿主 loopback 不可达。Linux 测试入口拒绝未隔离运行。
5. 补录必须注明新的采集时点。缺失的历史输入、模型和规则版本不得按今天的配置补成历史事实。

## 数据资格

`source_validity`、`judgment_outcome`、`allowed_uses` 分开。来源有效但预测错误，是负样本；不因后来亏损而删去。crash 样本不再免责排除。来源不明、测试混入和时点穿越不能进入建议/学习，但保留审计原件。

`integrity/eligibility.json` 是外部审核状态，资格绑定内容哈希及父证据哈希。`integrity/exclusions.jsonl` 是追加排除清单。Markdown、SQLite、工具检索和缓存共用资格规则；SQL/向量事件召回应用排除清单。历史数据恢复不能恢复已撤销资格。

Dreaming 的旧评分只作描述和影子诊断。LLM 验证异常/缺项/重复 ID 为 PENDING；明确 REJECT 才删除候选，原始负样本不删除。发布须同时具备来源资格和独立评估，LLM 的 KEEP 不构成发布授权。

HOLD 的窗口涨跌、用户实际持仓收益、可执行替代方案收益是三种不同量。不能把“下跌时 HOLD”直接称为躲跌，或把“上涨时 HOLD”一概称为踏空。旧 flat-band 仍可用于诊断，不能用作经济优势证明。

## 不可变决策与等待条件

prepare 返回独立 context_id，保存实际输入、完整提示词、账户文档、代码/配置及资格版本。提交必须绑定该编号；过期、跨标的、配置/账户/资格变化时重新准备，不读取“该标的最近一次”的快照兜底。

同一 context_id 的相同提交幂等；不同正文拒绝覆盖。原始建议、后处理建议、改写规则、未知执行状态分开保存。历史每日文件继续供旧接口读取，每次运行另有不可变证据和正文。

风险退出、投资理由失效、流动性需求，不要求承诺更低买回价。择时买回型退出的旧校验保留作对照。期末收益分布不能当成途中触价概率。防御只在后端统一执行，避免提示词先改 HOLD 后遮蔽允许分批的例外。

CIO 必须分别比较继续持有、增加仓位、降低风险和择时卖出后买回。模型建议的新价位不能成为既有用户止损规则；未知损失承受度不能从现金余额推算，也不能自行变成必须持有或必须卖出的门槛。金额限制以同一份有效币种换算结果进入分析与执行校验；换算缺失不得把原币金额冒充目标币金额。

原始 CIO 回复先保留，再对来源引用、时点与单位、算术、内部一致性、约束权限、退出目的和概率事件定义作有限核验。正确 HOLD 可以通过，主观风险收益权重不同本身不算逻辑错误。核验通过不授予来源、学习或交易权限；逻辑错误、核验不可用、核验格式错误分别记录，均不能冒充市场 HOLD 或有经济价值的拦截。未通过核验不激活新计划，也不完成绑定的风险分析待办。

角色调用状态由调用方记录，在文本修饰和 JSON 备忘提取前保存，解析与落盘共用。模型引用或否定错误标记，不是调用失败证据；旧格式仅兼容完整错误行。账户、鉴权或模型配置失败应停止后续综合，返回无提案的 UNCLEAR/DATA_UNTRUSTED，不能在健康检查中改成市场 HOLD，也不能登记没有草稿的“等待核验”。失败前已取得的各轮原文及调用状态进入不可变审计，第二轮不能被最后一轮冒充。可见失败摘要仅含错误类型及状态，不把提供商异常正文当作市场证据转交模型。

核验缓存绑定提案、来源、核验提示词及实现、模型与调用配置。Coordinator 的无后端模型路径先保存草稿并发出绑定请求，再提交独立核验；不得在首次提交时通过可选 JSON 绕过后台核验。失败后继续处理保存的提案，不重复生成整套委员会来追求某个方向或通过结果。

最终综合和核验分别记录实际思考模式；前面有多名分析员不能证明最终调用已经思考。DeepSeek 的最终两角色默认开启独立思考，JSON 结构化输出同时保留。显式兼容覆盖须可见，不能把开启思考暗中改成文本解析。逻辑核验改善不构成收益或预测改善证明。

等待计划保存 plan_id、条件、单位、有效期、创建输入和变更理由。达到条件仅要求复核，不授权下单。更换计划必须引用旧编号和理由；已触发的提醒保留在独立通知队列，不能因随后改了计划而消失。

计划另存不可变内容凭证，绑定父决策、用途和条件。实际进入模型的合格旧计划须作为新上下文的父依赖递归核对，不能经一代新计划洗掉已撤销的旧来源。普通等待计划不能凭同一旧编号移植为风险退出计划。旧父证据未知时只显示质量提示和替换编号，不再把旧价位放回账户事实；已记录的条件和提醒仍保留审计。独立质量巡检现场核对资格，不依赖最近一次出题留下的缓存。新证据支持相同条件时，允许带原编号和理由重新论证，无须为恢复资格而移动价位。计划期限与建议缓存期限分别处理。

## 阈值与影子比较

`core/rule_audit.py` 列出关键规则族、全部配置参数和数值作用位置。市场判断参数、用户约束、数据安全、运维限制、评分定义分别处理。

来源采集保存响应、条目及观察版本。应用内部定位符必须绑定对应提供商的原始响应；它不是来源网站网页。来源快照、父响应和派生事件共用撤销链。撤销后的原文仍可审计，不能继续归一化或进入建议。SQLite 的未完成状态为权威，JSON 回执不能掩盖它；旧格式队列只能明确迁移或作为待重新核对的审计记录，不能伪装成新取得的来源。

来源报道用途还必须校验采集真实性。普通 Agent 自填摘要、旧行仅有网址/标题、任意输入被队列封存，都不能证明后端确实取得了这些报道。API 输入须逐项匹配本实例不可变响应，并绑定服务器接收凭证与实际保存时间；受控适配器输出须绑定真实调用的采集器、代码版本、请求及取得时间。两者仅允许作为“该渠道提供的报道”参与分析，不证明报道内容为真，也不授予学习或发布资格。旧有效来源可通过内容绑定核对追认；判断结果错误不影响此资格。

事件语义版本与实际归一化输入关联；可信来源不能替同一事件下的未知文字或新写入摘要背书。get/list/recall/指定事件和历史读取共用此门禁，先过滤再取前若干条。未知修订保留冲突审计，不能覆盖已有可信版本。内部价格观察另存本实例生产者凭证，事件类型或“backend”标签不构成通行证。

来源被隔离的数量、原因和核验故障进入独立质量状态；分析待办保留 verification_required，不能算作已完成或已撤销。采集异常和成功取得零条分别记录，来源首次调用失败也应告警。关键词仅决定处理优先次序，不能永久遮蔽已取得的候选。

跨实例公开新闻同步须另有完整事件及来源内容绑定的 publish 审核；公开域名不能许可公开用户的归一化摘要。同步保留为目标实例审计输入，明确返回待核验用途，不移植源实例的采集身份或正面学习授权；目标须取得自己的来源凭证或完成内容绑定核对后才可用于建议。上游撤销与目标已有排除保留。

没有依据不等于删除后一定更好。保留原规则作用、无约束候选分析及差异理由；研究结果不足时不切换生产市场参数。修复明确的语义错误不宣称提高收益。用户资金限制、成交安全和评价标准不进入自动调参白名单。

历史条件统计、无条件基率和混合后结果须同时可审计，并展示混合权重、数据日期截止及算法/配置版本。`n/窗口天数` 仅为样本量启发式，不能证明样本独立。当前日期截断不等于恢复当时实际可得的行情版本。

预测用途另外校验生成器的代码和参数，以及绑定的数据、评估、协议父证据。披露来源不等于获得预测资格；未获准的历史概率不进入委员会决策输入，也不填成中性概率或强制 HOLD。当前行情、分类所用观测和原始审计记录保留。重新计算基线只接收原始条件统计，不能混入已校准 live 结果；跨训练边界的未成熟标签剔除，脚本诊断 PASS 不构成发布许可。

## 冻结评估协议

评估前固定事件定义、日历期限、模型版本、输入可用时间、成交时点、币种、成本依据、基准、主指标、风险约束、观察范围、独立日期块和样本充分性依据。

训练、验证、最终评估按时间隔离，跨边界标签剔除。重复运行不重复计数；多资产共享日期块，不能用同一市场事件制造独立样本量。全部候选事先登记，最终评估窗口使用后不能改名/切片再给另一候选反复试验。覆盖不足、结果未成熟、真实行情结果缺失均阻止发布。

所有可核验建议均可评估，包括用户未执行的建议。市场结果、模拟执行效果和真实成交分开；自报 confidence 不直接转换为事件概率。模型变化后重新判断资格；固定日期或模型自报知识截止不能证明历史回放干净。

## 发布与回退

自动学习发布默认关闭，参数白名单为空。每次发布绑定代码、数据、特征、模型、提示词、规则、参数、协议及研究授权版本。评价、独立评审和回退目标分别登记，发布请求不能自行认证。

至少五个交易日的影子观察只验证工程稳定性，不能代替长期收益验证。市场参数发布还需最终评估、完整覆盖、风险约束和三方独立评审；每周频率限制只是附加条件。

数据隔离、明确语义错误和通知修复可以在工程验收后作为安全修复发布；没有通过金融评估的市场参数继续影子比较。不能为等待统计样本而让污染继续传播，也不能把工程验收当作策略胜出。

回退只恢复决策版本/参数，保留最新排除、研究撤回和删除状态，不覆盖新的真实交易。恢复数据库后默认阻止账本写入和分析，先核对订单、成交、现金、持仓、幂等状态。旧依赖不再合格时停用受影响建议并明确显示 DATA_UNTRUSTED。

托管研究导出和训练启用前重新核验当前研究参与、epoch、政策版本、删除状态、文件哈希和用途。有效错误样本可保留；只有工具成功返回、没有市场结果的记录不能当成金融预测真值。

## 告警

质量告警独立于行情交易提醒及全 HOLD 静默策略。持续同一裁决、输入不可信、等待条件达到/过期/被无理由修改，应进入质量复核。告警不要求凑交易比例。双通道均未成功时不得标记已发送；保留队列重试。日程恢复、通知投递和运行实例版本都须在部署后核对。

## 自动任务与调用成本

无人值守投资任务使用固定脚本入口 `python -m openinvest.jobs.fixed_invest`，通过共享后端委员会完成角色判断和独立核验。宿主 cron 使用脚本模式，不注入通用聊天记忆、人格或第三方交易技能。日报默认两轮辩论，不自动增加翻译或额外模型复核；交互入口保留原有默认值。采集和历史核对均不需要模型调用。

日报先保存完整结果，再由持久通知队列分别投递邮件正文和 Discord 摘要；重复执行仅补投，不能为通知故障重新生成委员会。正文邮件未被接受不能报完整日报成功，已有失败或降级结果也不能在重试时改名成功。旧建议失去资格时，待发送的旧正文撤下，改发质量提示。

来源归一化在付费操作前保存快照尝试。中断或部分返回后未确认入库的快照保留待核对，不自动再次付费。实际待处理快照状态决定完成数量，送模型不等于完成；回执损坏须显式失败。处理批量限制只约束本次成本，不取消未处理来源的资格。

刚取得的旧原文仍保留原发布时间。没有可核验的发布方修订时间时，不能靠取得时间或自填字段把它改成当前新闻；可能的旧文修订保留审计并待核对。当前报道窗口来自配置，与买卖方向门槛分开。

上线验收还须核对实际 HTTP 委员会服务与固定脚本使用相同的已审代码和模型配置。只验证脚本的解释器，不能证明其下游服务身份。恢复任务前，必须完成原生 cron、真实通知回执与各运行实例的核对。
